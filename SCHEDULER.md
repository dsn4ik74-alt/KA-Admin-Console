# Планировщик · 20.33.7

Проверки разных комплектов RAS перед подключением — диагностические попытки.
Отказ одной версии при переходе к следующей сохраняется как предупреждение,
даже если RAC написал «Ошибка установки соединения». Когда совместимый комплект
найден и действие завершилось успешно, шаг и вся цепочка не получают ложных ошибок.
Если ни один комплект не подошёл, итоговая ошибка останавливает последовательность.
Ошибки самой операции создания, удаления или настройки ИБ остаются ошибками;
изменяющие команды автоматически не повторяются.

Кнопка **Вкл./выкл.** работает с выбранным сохранённым расписанием слева.
Если оно открыто справа и вы изменили дату, время или действия, при включении
будет предложено сохранить эти изменения. Подтверждение изменяющих данные
действий сохраняется. Отмена или ошибка сохранения оставляет задание выключенным.
После переключения галочка «Включена» в открытом редакторе обновляется.

Для однократного запуска нужно будущее время по часам компьютера консоли.
Если сохранённое время прошло, сообщение покажет его и текущее время ПК.
В 20.33.5 новые значения справа нужно сначала сохранять кнопкой
**Сохранить расписание**, установив **Включена**. Это сразу активирует расписание.
Выключенное расписание можно сохранить с прошлой датой.

В 20.33.5 исправлена ошибка «Не найдена утилита …\Temp\_MEI…\vendor\postgresql…».
Путь `_MEI…` существует только в течение одного запуска EXE. При сохранении
используется относительная ссылка на встроенный инструмент; старые абсолютные
пути автоматически переводятся в каталог текущего процесса, включая получателя
и список версий `pg_restore`. Пересоздавать расписание не нужно.
Свои установленные утилиты и SSH-пути сохраняются без подмены.

После обновления EXE остановите прежний фоновый исполнитель и включите фоновый
запуск из новой сборки: уже работающий старый EXE сам код не обновит.

## Создание последовательности

1. Настройте действие в обычной вкладке: подключение, базы, пути и параметры. Нажмите **«В планировщик ▾ → Добавить текущее действие»**.
2. Перейдите в следующую вкладку и добавьте её действие. Например: PostgreSQL «Бэкап + восстановление», затем «Добавление ИБ в кластер». Из планировщика кнопка «+ Действие…» открывает нужную форму.
3. В конструкторе меняйте порядок стрелками, редактируйте параметры и убирайте ненужные шаги. Это снимки настроек: последующее редактирование обычных вкладок не меняет сохранённые действия.
4. Укажите название, дату и локальное время компьютера консоли. Доступны один запуск, ежедневный, выбранные дни недели и интервал в минутах.
5. Нажмите **«Сохранить расписание»**. Изменяющие данные действия подтверждаются при сохранении; затем выполняются без дополнительных вопросов. Для самостоятельного фонового исполнения включите его, как описано ниже.

Если восстановление должно использовать файл отдельного предыдущего шага, в его параметре пути можно указать `${previous.backup_path}`. Предыдущий шаг должен вернуть ровно один файл/каталог бэкапа. Готовая операция «Бэкап + восстановление» связывает этапы сама.

Поддержаны SQL Server/PostgreSQL-бэкап, восстановление и цепочки, создание/удаление БД, выгрузка/восстановление DT, добавление/удаление регистрации ИБ, блокировка заданий, службы Windows, архивирование ЖР, создание локальных пользователей, установка 1С из ИТС и собственная команда PowerShell. Дополнительные действия СУБД и кластера доступны в меню «В планировщик». WinDirStat, проводник и MMC являются интерактивными окнами и не запускаются по расписанию.

Для установки сначала подготовьте и проверьте дистрибутив в обычной форме. Сохраняются конкретная версия, компоненты и подключение; во время запуска дистрибутив заново скачивается с ИТС, проверяется и устанавливается существующими обработчиками. Собственный локальный каталог загрузки удаляется в конце. Первое доверие SSH нужно подтвердить заранее кнопкой проверки: фоновый процесс не показывает диалоги.

DT по-прежнему требует заранее обеспечить отсутствие обращений других процессов 1С. Подтверждающий флажок не останавливает пользователей автоматически. Запланированное восстановление завершает подключения к целевой базе и заменяет её данные, как и ручное восстановление. При ошибке или отмене последующие шаги пропускаются; сделанные изменения автоматически не откатываются.

## Работа после выхода из Windows

Откройте **«Планировщик → Фоновый запуск… → Включить / обновить»** и введите пароль текущей учётной записи Windows, не PIN.

Приложение регистрирует только собственную задачу `KAConsole Scheduler <идентификатор>` в штатном Планировщике Windows. Она запускается под той же учётной записью с наивысшими правами и `TASK_LOGON_PASSWORD`, при загрузке компьютера и повторной проверке раз в минуту. Внутри постоянно работает отдельный EXE с аргументом `--scheduler-worker`, без интерфейса. Это сохраняет доступ к сетевым подключениям и DPAPI даже без интерактивного сеанса. [Модель входа Microsoft](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks).

Пароль Windows передаётся через stdin штатному API регистрации, не попадает в аргументы запуска или файлы приложения. Его хранит Windows своими средствами. Пароли СУБД, 1С, ИТС и SSH защищены DPAPI текущего пользователя. Другую учётную запись выбрать нельзя: она не расшифрует эти данные.

Консоль можно закрыть, заблокировать сеанс или выйти из Windows. Компьютер должен быть включён. Запрашивается пробуждение, но его доступность зависит от настроек питания. При смене пароля Windows или перемещении/обновлении EXE заново нажмите «Включить / обновить».

Сетевые диски, подключённые только в интерактивном сеансе, заменяйте доступными этой учётной записи UNC-путями. Ключ только из SSH-agent после выхода может быть недоступен: используйте доступный файл ключа или пароль.

«Отключить» удаляет собственную задачу Windows и даёт активной цепочке закончиться штатно. Кнопка «Прервать запуск» запрашивает отмену текущего действия и запрещает следующие шаги. Некоторые операции, например создание УЗ, сначала заканчивают собственную обработку; следующая операция уже не запускается.

## Ошибки, пропущенное время и история

- Исполнитель запускает одну цепочку за раз, без наложения восстановлений. Ручные вкладки остаются независимыми. Во время фоновой цепочки сверху появляется мигающий зелёный индикатор, открывающий планировщик.
- По умолчанию задержка более пяти минут означает пропуск с записью в историю. «Запускать пропущенное» разрешает один запуск после включения/восстановления работы, без воспроизведения всех накопленных повторений. Пропущенные интервалы во время работы той же цепочки не запускаются поверх неё.
- Автоматического повтора операции при ошибке нет. Следующее повторение по расписанию — самостоятельный запуск.
- После аварии/перезагрузки незавершённая цепочка помечается **«Не завершено»**, оставшиеся шаги пропускаются и её расписание отключается до проверки и явного включения. Состояние реальных баз необходимо проверить перед новым запуском.
- Таблица расписаний показывает статус, последнее/следующее время, длительность и число сообщений об ошибках.
- История раскрывается **день → запуск → действия**. Видны начало/окончание, длительность, статус и ошибки каждого шага. Выделение открывает журнал; обе границы панелей растягиваются.
- Журнал зелёный на чёрном, предупреждения жёлтые, ошибки красные. Полный журнал остаётся на диске; текст в окне загружается порциями. Раскрытые строки и позиция просмотра сохраняются. «Ещё 100» открывает более ранние запуски.
- **«Результат шага…»** показывает отдельный защищённый результат. Для создания УЗ там находятся созданные пользователи и пароли; пароли не выводятся в общий журнал.
- Удаление расписания не удаляет историю. Выполняемую цепочку нельзя редактировать или удалить.

## Хранилище и проверка

Файл: `%LOCALAPPDATA%\KAConsole\scheduler\scheduler.sqlite3`. Полные параметры и результаты зашифрованы DPAPI; имена расписаний, статусы и очищенные журналы доступны для чтения в SQLite. Файл блокировки рядом защищает от нескольких исполнителей между сеансами Windows. SQLite WAL, короткие транзакции, пакетная запись журнала и постепенное чтение не блокируют интерфейс. Сама форма создаётся только при первом открытии; в других вкладках читается небольшой статус исполнителя.

Проверки используют временные SQLite и тестовые учётные данные. Проверены расписания, конкурентный захват, порядок шагов, остановка при ошибке/отмене, восстановление после обрыва, защита параметров и результатов, маскирование журнала, перенос путей встроенных утилит между запусками EXE и интерфейс. Отдельный настоящий процесс исполнил два безвредных шага PowerShell без создания Tk. Задачи Windows на компьютере разработки не регистрировались; настоящие базы и установки не запускались.
