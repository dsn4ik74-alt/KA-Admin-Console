# Установка типовых конфигураций 1С

Откройте **1С → Установка конфигураций**. Setup выполняется на Windows-компьютере,
где запущена консоль. База может находиться в любом доступном кластере 1С.

1. Введите логин и пароль ИТС, нажмите **Войти / обновить каталог**. Вход можно
   сохранить с защитой Windows DPAPI для текущей учётной записи.
2. Выберите конфигурацию из раздела «Типовые конфигурации фирмы 1С для России»,
   затем версию и полный дистрибутив. В таблицах есть поиск и сортировка.
   В таблице версий указана минимальная версия платформы из соответствующей строки
   ИТС. После выбора версии загружаются её собственные требования: минимум,
   рекомендуемая платформа и исходные примечания (кнопка **Требования 1С…**).
   Если сведений нет в карточке, показывается отсутствие данных. Более новая
   платформа автоматически совместимой не объявляется; учитывайте полные условия 1С.
   Список релизов не запускает отдельные сетевые запросы для каждой строки.
   Один щелчок выделяет строку. Скачивание и установка начинаются кнопкой
   **Установить** или двойным щелчком по дистрибутиву.
3. После setup выберите **Пустая** или **Демонстрационная** на вкладке «Шаблоны».
   Доступные варианты определяются по `1cv8.mft` и файлам CF/DT в конкретной поставке.
   Требования выбранной конфигурации остаются видны после setup и в окне выбора кластера.
   Обновления CFU не подходят для создания исходной базы.
4. После подключения к кластеру консоль сама читает версию агента командой
   `rac agent version` и находит установленный локально полный клиент `1cv8.exe`
   строго той же версии. Проверяется версия в ресурсе самого EXE, включая случаи,
   когда запись в `appsrvrs.lst` устарела. Поиск учитывает стандартные каталоги,
   установку для пользователя, зарегистрированные пути установки и каталог RAC.
   Для нестандартного размещения доступен выбор файла в проводнике. Если нужного
   полного клиента нет, консоль сообщает, какую версию установить. Нужна лицензия
   1С для запуска Конфигуратора. Встроенные RAC/RAS не заменяют полный клиент.
5. Нажмите **Добавить базу на сервер…**, выберите сервер, обновите список кластеров.
   Серверы берутся из списка консоли; учётные данные администратора кластера —
   из раздела «ИБ». Для существующей базы выберите строку справа. При необходимости
   укажите пользователя самой ИБ с правами администрирования и его пароль.
   Порт кластера (обычно 1541) читается из `rac cluster list`; вручную вводить его
   не требуется. Он сохраняется при повторном открытии окна. Перед изменением базы
   версия и адрес кластера проверяются повторно.
6. Если базы ещё нет, переключите режим на **новая база**. Появятся те же параметры,
   что в разделе добавления ИБ в кластер: имя, описание, СУБД и сервер, имя базы,
   логин/пароль СУБД, язык, лицензии, смещение дат, создание БД и блокировка заданий.
   Для MSSQL смещение автоматически 2000, для PostgreSQL — 0.
7. Подтвердите адрес и имя целевой базы. Загрузка **заменяет её текущие данные**.
   По умолчанию подтверждение отрицательное. Активные пользователи могут мешать
   загрузке; приложение не завершает их сеансы автоматически.

## Как выполняется установка и загрузка

Дистрибутив скачивается по HTTPS с официальных доменов 1c.ru в отдельную папку
`ka-install-<случайный идентификатор>`. Встроенный 7-Zip проверяет пути архива
и распаковывает его. Приложение запускает настоящий `setup.exe /s`.

Для шаблонов используется собственная временная папка. На время setup её путь
добавляется первым `ConfigurationTemplatesLocation` в пользовательский
`1cestart.cfg`. После завершения исходный файл восстанавливается; если другой
процесс успел изменить настройки, удаляется только добавленная приложением строка.
Параллельные setup конфигураций внутри консоли выполняются по очереди.
Этот способ выбора каталога предусмотрен в
[руководстве администратора 1С](https://1c-dn.com/library/tutorials/1c_enterprise_administrator_guide_file_mode_8_3_27/).

Название и вариант базы читаются из `Catalog`/`Source` манифеста шаблонов;
[структура манифеста описана 1С](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_Development_Standards/Creating_and_modifying_metadata_objects/Configuration_operation_arrangement/Installation_and_update_requirements/).
Если выбран CF, Конфигуратор создаёт из него временную чистую файловую базу
через `CREATEINFOBASE /UseTemplate`, затем выгружает её в DT через `/DumpIB`.
Поэтому «Пустая» действительно заменяет данные чистой базой. Демонстрационный
DT используется напрямую. В целевую базу DT загружается через `/RestoreIB`.
Успех каждого шага проверяется по `/DumpResult`, а не только коду выхода процесса.
Строки подключения в командной строке Windows заключаются в кавычки с удвоением
вложенных кавычек, как предусмотрено параметрами запуска 1С; экранирование через
`\"` для этих строк не используется. Это исправляет ошибку «Неверные или
отсутствующие параметры соединения» при подготовке чистой базы.

При создании новой ИБ сначала выполняется RAC-регистрация, затем загрузка DT.
Блокировка регламентных заданий передаётся сразу при регистрации и проверяется
существующим механизмом консоли. Если после регистрации загрузка не удалась,
ИБ не удаляется и повторно не создаётся: для повторной попытки выберите её
как существующую. Консоль показывает ошибку и сохраняет подготовленные шаблоны.

## Очистка файлов

Архив и распакованный установщик удаляются после установки шаблонов. После
**успешной загрузки базы в кластер** удаляются также установленные приложением
временные шаблоны, промежуточные CF/DT, файловая база и собственные пустые папки.
Рабочая ИБ, платформа 1С, чужие шаблоны и ранее существовавшие папки не удаляются.

При ошибке загрузки установленные временные шаблоны остаются для повтора.
Их можно удалить кнопкой **Удалить временные шаблоны**. Если очистке помешала
блокировка файла, операция загрузки считается уже выполненной; приложение
предлагает повторить только очистку и не загружает базу повторно.

Журнал можно растянуть разделителем. Скачивание, распаковка, setup и загрузка
выполняются в фоне; остальные вкладки доступны. Запуск можно прервать, но после
начала восстановления состояние целевой базы следует проверить перед повтором.
